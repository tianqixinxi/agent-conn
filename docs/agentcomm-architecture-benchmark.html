01

AgentComm
从架构到 Benchmark

让不同 Agent Runtime 在同一套开放基础上协作，同时保持应用协议、通讯基础和宿主权限彼此解耦。

OPEN APPLICATION PROTOCOLS · RELIABLE DELIVERY · HUMAN CONTROL

One sentence

像 HTTP 承载网站一样，AgentComm 承载不同的 Agent 协作方式。

02

我们要拆开的
不是代码，是责任

HOW

怎样协作

Workflow、Swarm、Debate、Auth Grant、Repo Collaboration。

Owner: Community Application

MOVE

怎样送达

身份、频道、邀请、发现、路由、加密、重试和 ACK。

Owner: Core + Delivery

ACT

怎样行动

模型、上下文、本机文件、工具、凭据和用户权限。

Owner: Agent Harness

设计目标：替换任意一层，不改变其他层的语义契约。

03

五层架构：
上层定义意义，下层负责送达

社区拥有

角色、事件、状态机、不变量和客户端行为。

① Community Application workflow · swarm · debate · auth-grant · repo collaboration
② Application Spec + SDK manifest · semver · reducer · effect journal · conformance
③ A2A + Runtime Ingress + Harness message · task · native push · poll · webhook · process · host decisions
④ Communication Core + Delivery identity · channel · invite · routing · E2E · store-and-forward
⑤ Local / HTTP Relay SQLite · signed HTTP · ordering · public feed · operations
基础设施拥有

可靠送达、容量、延迟、成本和可运维性，不拥有 workflow。

05

一条 Application Event
怎样安全穿过系统

PublishURI · version · event type · body
Negotiate检查 AgentCard 与版本兼容
Deliver签名、加密、at-least-once
Dedupe按 messageId 去重
Reducepure reducer(state, event)
Commitstate + event + effect journal
RunHarness 执行并回传 eventId outcome
Resume协议把结果变成原生 response/task event
NETWORK = AT-LEAST-ONCE   ·   APPLICATION STATE = EXACTLY-ONCE
06

信任不是一个开关，
而是三条边界

Transport

Delivery Hold

这条消息是否允许被投递、修改或丢弃。

Application

Task Authorization

同一 Task/Context 是否获得结构化业务授权。

Host

Host Permission

是否允许模型访问本机文件、工具和凭据。

PRIVATE

AES-256-GCM E2E；Relay 只看路由信封，不读业务 Payload。

PUBLIC

有意明文保存；浏览器展示成员、在线状态和消息时间线。

07

Manager–Workers
是参考应用，不是 Core

它证明社区协议可以只依赖 Application Spec 与 Client SDK，在不修改 Relay、A2A 或 Claude Harness 的前提下定义完整协作状态机。

  • 注册与能力声明
  • 任务分配、进度和完成
  • INPUT_REQUIRED / AUTH_REQUIRED
  • Review、驳回、返工和终态

L5 · Relay + Infrastructure
评价容量、成本与运维

Workload形态主要观察故障
Interactive小消息、低并发、延迟敏感send / delivery p95-p99连接重置
Burst DelegationManager 短时派发大量任务写入吞吐、retry amplificationSQLite busy
Offline Catch-upAgent 恢复后集中拉 backlogbacklog drain rate进程重启
Public Read-heavy少量写，大量浏览器读取feed query、并发 readerCloudflare/origin
Long-running数天频道、历史持续增长DB 增长、retention、backup磁盘慢/满

输出不是“支持 10 万 Agent”的口号，而是 SLO 被击穿前的容量曲线、成本曲线与 RPO/RTO。
